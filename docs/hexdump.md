# 🖨️ 第三方组件（hexdump 内存转储）

> 🎯 本文介绍 LinCLI 内置的轻量级 `hexdump` 组件，帮助你在嵌入式/MCU 调试时快速查看内存内容～ ✨

---

## 🧩 1. 组件概述

**hexdump** 💻 是一个专为嵌入式环境裁剪的内存转储工具，支持：

- ✅ 按指定地址和长度 dump 内存内容
- ✅ 十六进制 + ASCII 双列显示
- ✅ 可配置的地址范围保护（防止误读非法地址）
- ✅ 自定义每行字节数（1 ~ 64）
- ✅ 彩色终端输出：🔵 地址列蓝色、🔷 ASCII 列青色
- ✅ 表头自动显示 `addr` / `value` / `ascii` 与分隔线

它的**核心定位**是：

> 📍 **在 CLI 交互式终端中快速查看任意内存地址的内容，辅助调试硬件寄存器、Flash、SRAM 等。**

---

## ⚙️ 2. 开启配置（make menuconfig）

```bash
cd /path/to/LinCLI
make menuconfig
```

在菜单中依次进入：

```
Third Party Components
  └── [*] Enable hexdump support
```

✅ 勾选后按 `S` 保存，按 `Q` 退出。重新编译即可生效：

```bash
make
```

> 💡 可通过 `HEXDUMP_MIN_ADDR`、`HEXDUMP_MAX_ADDR`、`HEXDUMP_BYTES_PER_LINE`、`HEXDUMP_MAX_LEN` 配置默认值。

---

## 📋 3. 命令选项详解

### 🔹 基础用法

```bash
hexdump -a <addr> [-l <len>] [-C]
```

| 选项 | 类型 | 说明 | 示例 |
|------|------|------|------|
| ✅ `-a` / `--addr` | INT | 📍 起始地址（支持十六进制） | `-a 0x08000000` |
| ✅ `-l` / `--len` | INT | 📏 要 dump 的字节数（默认 `max_len`） | `-l 64` |
| ✅ `-C` / `--ascii` | BOOL | 🔤 显示 ASCII 字符列 | `-C` |
| ✅ `-s` / `--show` | BOOL | 📊 显示当前配置 | `-s` |

### 🔹 配置模式（`--config`）

> ⚠️ **改进点**：为了支持将 `min_addr` 配置为 `0x0` 等特殊值，配置选项已统一归入 `--config` 模式下使用。

```bash
hexdump --config -m <min> -M <max> [-b <bytes>]
```

| 选项 | 依赖 | 说明 | 示例 |
|------|------|------|------|
| ✅ `--config` | — | 🔧 启用配置模式（用于 `-m` / `-M`） | `--config` |
| ✅ `-m` / `--min-addr` | `config` + `M` | 🚧 设置最小合法地址 | `-m 0x08000000` |
| ✅ `-M` / `--max-addr` | `config` + `m` | 🏁 设置最大合法地址 | `-M 0x0800FFFF` |
| ✅ `-b` / `--bytes-per-line` | — | 📐 设置每行显示字节数（1 ~ 64） | `-b 16` |

> 💡 使用 `--config` 后，配置会立即生效并打印当前配置信息。

## 🧪 4. 使用示例

### 🔹 示例 1：查看当前配置

```bash
admin@linCli> hexdump -s
hexdump config:
  min_addr       : 0x08000000
  max_addr       : 0x0800FFFF
  bytes_per_line : 16
  max_len        : 256
```

### 🔹 示例 2：修改配置范围

```bash
admin@linCli> hexdump --config -m 0x00400000 -M 0x00401000
hexdump config:
  min_addr       : 0x00400000
  max_addr       : 0x00401000
  bytes_per_line : 16
  max_len        : 256
```

### 🔹 示例 3：Dump 内存（含 ASCII）

```bash
admin@linCli> hexdump -a 0x00400000 -l 64 -C
    addr                         value                             ascii
-------------------------------------------------------------------------------
0x00400000: 7F 45 4C 46 02 01 01 00 00 00 00 00 00 00 00 00  |.ELF............|
0x00400010: 02 00 3E 00 01 00 00 00 F0 30 40 00 00 00 00 00  |..>......0@.....|

0x00400030: 00 00 00 00 40 00 38 00 0D 00 40 00 30 00 2F 00  |....@.8...@.0./.|
```

> 🎨 输出效果说明：
> - 🔵 `addr` 标签与地址列均为 **蓝色**

## 🐧 5. Linux 地址禁区与段错误

### ⚠️ 为什么在 PC Linux 上 dump 某些地址会段错误？

在 MCU（如 STM32）上，内存地址是**物理地址**，Flash 从 `0x08000000` 开始，SRAM 从 `0x20000000` 开始，这些地址是固定的、始终存在的。但在 **PC Linux** 上，程序使用的是**虚拟地址**，地址空间中有大片区域根本没有映射物理内存。

#### 🚫 军事禁区：`0x0000 ~ 0x0FFF`（第一页 4KB）

Linux 内核默认将**虚拟地址空间的第 0 页**（`0x00000000` 到 `0x00000FFF`）设为禁区：

- 🛡️ **防止 NULL 指针解引用**：`*(int *)0` 会立即段错误，而不是静默破坏数据
- 🛡️ **防止近 NULL 偏移访问**：结构体指针为 NULL 时，`ptr->field`（偏移几个字节）也会触发段错误
- 🔒 由 `mmap_min_addr` 内核参数控制（默认 4096），用户空间无法映射这一页

> 🐛 **结论**：`0x00000000` 及附近低地址在 Linux 上是**绝对不可读**的，这是内核强制保护，不是程序限制。

#### 🏜️ 荒地：未映射的虚拟地址

除了第一页禁区，Linux 进程的地址空间中还存在大量**未映射的空白区域**（荒地）：

| 区域 | 典型地址范围 | 状态 |
|------|-------------|------|
| ✅ 代码段（.text） | `0x00400000` 附近 | 🟢 已映射，可读 |
| ✅ 数据段（.data/.bss） | 代码段之后 | 🟢 已映射，可读可写 |
| ✅ 堆（heap） | 较高地址 | 🟢 已映射，动态增长 |
| ✅ 栈（stack） | `0x7fff...` 附近 | 🟢 已映射，动态增长 |
| ❌ 中间空白区 | 因程序而异 | 🔴 未映射，读则段错误 |

> 💡 **关键区别**：
> - `0x0 ~ 0xFFF`：**内核强制保护**，任何程序都不可读
> - `0x1000` 及以上：**可以映射，但当前未映射**。你的程序没有在这片地址分配内存，页表里没有记录，读就会段错误

#### 🔧 如何避免段错误？

1️⃣ **使用程序自身的合法地址**

在 PC Linux 上测试时，使用 ELF 可执行文件的代码段起始地址（通常是 `0x00400000`）：

```bash
hexdump --config -m 0x00400000 -M 0x00401000
hexdump -a 0x00400000 -l 64 -C
```

2️⃣ **确认地址是否在你的配置范围内**

```bash
hexdump -s
```

确保 `dump_addr >= min_addr` 且 `dump_addr + len <= max_addr`。

3️⃣ **嵌入式/MCU 环境无需担心**

在 STM32 等裸机环境中，物理地址是固定的，`0x08000000`（Flash）和 `0x20000000`（SRAM）始终可读，不会段错误。

## 🔧 6. 自定义读取函数

`hexdump_default_read` 被声明为弱符号，你可以在自己的文件中覆盖它：

```c
uint8_t hexdump_default_read(uintptr_t addr)
{
    /* 自定义读取逻辑，例如通过串口读取外部设备内存 */
    return my_custom_bus_read(addr);
}
```

覆盖后，`hexdump` 命令会使用你的自定义读取函数，无需修改 `hexdump.c` 源码。

---

## 📌 7. 注意事项

- ⚠️ `hexdump_default_read` 在 MCU 上直接解引用指针，请确保地址指向合法内存（寄存器、Flash、SRAM）
- ⚠️ 在 PC Linux 上测试时，务必使用**已映射的合法虚拟地址**，否则触发段错误
- 💡 使用 `-C` 选项可同时查看 ASCII 字符，方便识别字符串内容
- 💡 使用 `--config` 模式时，`-m` 和 `-M` 必须成对出现，否则依赖检查会报错
- 💡 `-b` 可在任意模式下独立使用，无需 `--config`
